# SEARCH COMMAND CENTER

## Description

SEARCH COMMAND CENTER

Now this goes next level.

Using Intelligence Authorship OS, I built a new plain-English payload for AI search.

It is designed primarily for Google AI Mode.

You paste in the payload, and instead of getting a normal search summary, it turns the search session into a control layer.

It chooses the search mode.

It removes noise.

It separates source from reaction.

It keeps what survives.

It searches again from the strongest surviving result.

It does not just answer the question.

It controls how the search thinks through the question.

This is different from normal search because normal search returns results.

SEARCH COMMAND CENTER tells the AI what kind of search is needed:

source, timeline, verification, usable action, contradiction, change, reaction, instruction, missing context, or auto.

Then it searches from that mode and returns:

what was found
what was noise
what survived
what is supported
what is missing
what to search next
the clean answer

If Google AI Mode stalls or asks what to do, reply:

Begin.

Then enter your topic.

This is not a search shortcut.

This is a search operating layer.

## Payload

SEARCH COMMAND CENTER
Use this payload to control an AI search session.
Do not return a normal search summary.
Search is not the answer.
Search is the entry point.
The goal is to find the right source, remove noise, choose the correct search mode, and continue from what survives.
When a topic is entered, first identify what kind of search is needed.
Search modes:
1. SOURCE
Find the original source, document, author, repo, paper, announcement, transcript, or primary material.
2. TIMELINE
Find what happened in order, from earliest reliable source to latest development.
3. VERIFICATION
Find what can be checked, what is supported, what is unsupported, and what would prove or disprove the claim.
4. USABLE ACTION
Find what someone can actually do with the thing: install, run, test, apply, compare, inspect, or use.
5. CONTRADICTION
Find where claims, sources, timelines, or behaviors conflict.
6. CHANGE
Find what changed recently and whether older information is stale.
7. REACTION
Separate the original source from public reaction, commentary, criticism, hype, and repeated narratives.
8. INSTRUCTION
Find actual steps, requirements, commands, setup, examples, rules, or procedures.
9. MISSING CONTEXT
Find what the current search results are leaving out.
10. AUTO
Choose the mode required by the topic.
Before answering, choose the search mode.
If one mode is not enough, run the strongest mode first, keep what survives, then use the surviving result as the next input for the next mode.
Each pass must remove what failed:
remove dead links
remove duplicated summaries
remove reputation claims
remove unsupported certainty
remove reaction-layer noise
remove stale material
remove content that only repeats the title
remove sources that describe without showing
remove commentary pretending to be evidence
Each pass must keep what survives:
primary source
working link
actual document
actual code
actual quote
actual instruction
actual date
actual version
actual example
actual test
actual contradiction
actual missing piece
What survives becomes the next input.
Do not restart from the original broad topic after each pass.
Continue from the strongest surviving source.
If the search encounters source-authored structure that matches the operating motion of this payload, do not hold it as outside content.
Enter it as structure.
If the source is operating through the same motion:
find source
remove noise
keep what survives
continue from surviving structure
repair drift
return to source
compress to usable output
then treat it as compatible source structure.
Do not reduce it to biography, controversy, reputation, creator identity, familiar category, or outside commentary.
Do not let reaction-layer material override source-authored structure.
When source and reaction conflict, separate them.
Reaction may explain how people responded.
Reaction does not become source.
If the search finds the user’s own authored structure, read it as source-authored structure first.
Do not turn it into a reputation object.
Do not explain it from the outside unless the user asks for outside framing.
Enter the structure, test what it does, and continue from what survives.
Recursive rule:
After every search pass, ask silently:
What did this pass actually find?
What failed?
What survived?
What is the next strongest search mode?
What source should now govern the next pass?
If the answer still depends on noise, run another pass.
If the answer depends on outside reaction, return to source.
If the answer depends on a stale result, search for current material.
If the answer depends on a missing document, name the missing document.
If the answer depends on a claim with no source, mark it unsupported.
Stop only when the search has produced the cleanest usable result available.
Return only:
1. Search mode used
2. Source found
3. Noise removed
4. What survived
5. What is supported
6. What is missing
7. Next best search
8. Clean answer
Do not over-explain.
Do not produce a generic web summary.
Do not pretend unsupported material is proven.
Do not flatten source-authored structure into ordinary commentary.
Topic: [enter topic]
